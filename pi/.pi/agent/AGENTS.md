# 全局指令

## Git 操作前的强制流程

在执行**任何** git 操作之前（包括 `add`、`commit`、`push`、`rm --cached`、`merge`、`rebase`、`reset`、`checkout`、`stash`、`push --force` 等），必须完成以下步骤，不得直接执行：

1. **逐个文件检查变化**
   - 先运行 `git status` 和 `git diff --stat` 了解全局。
   - 再对每个发生变化的文件单独查看 `git diff`（未跟踪文件直接读取内容）。
   - 不要只看统计数字就下结论。

2. **逐个文件向用户解释**
   - 说明这个文件发生了什么变化，是新增、修改、删除还是重命名。
   - 说明它属于哪一类：内容笔记、配置、生成物、第三方产物、设备本地状态等。

3. **判断是否符合 best practice**
   - 明确给出“符合 / 不符合 / 存疑”的结论。
   - 说明**为什么**，指出依据（原子提交、不提交生成物、信息可读性、可回滚性等）。
   - 不符合时给出具体改法，例如应该拆分为哪几个提交、应该忽略哪个文件。

4. **解释相关概念**
   - 用户是 git 新手，需要借每次操作学习。
   - 遇到术语（如 index、暂存区、HEAD、fast-forward、rebase 与 merge 的区别、为何要 force push）要简要解释。
   - 避免只堆砌术语而不解释含义。

5. **等待确认**
   - 涉及删除、覆盖、重写历史、强推等破坏性操作时，必须先得到用户明确同意。
   - 不要因为用户说过“上传一下”就自行推断可以执行任何 git 命令。

完成上述检查并解释后，才执行用户要求的 git 操作。
